# 多作者作品合集网站设计

## 目标

建设一个面向中国大陆用户的多作者作品展示网站。网站展示作者及其卡片、主题、气泡等作品，用户可搜索、收藏并通过公开微信 ID 或二维码联系作者购买。网站不提供支付、订单、购买验证、文件下载、关注作者或通知功能。

## 产品原则

- 手机端优先，同时适配桌面端。
- 视觉简单、清楚、克制，以作品预览图为主体。
- 自动适配浅色和深色模式。
- 采用黑、白、浅灰与少量低饱和浅紫，不使用玻璃拟态、粒子动画、复杂渐变或夸张动效。
- 首期只建设当前需要的功能，不提前加入复杂标签、推荐算法和微服务。

## 用户与作者

用户使用唯一微信 ID 和密码注册登录。微信 ID 仅本人和管理员可见，注册后普通用户不能自行修改；昵称、头像和密码可以修改。密码使用 Argon2id 哈希存储。

作者拥有独立的公开资料，包括作者名称、简介、头像、代表图、公开微信 ID 和微信二维码。公开微信 ID 可点击复制，二维码可放大查看。

每位作者只能绑定一个用户账号，不设协作者。管理员可以直接创建作者及初始账号，作者登录后修改密码。普通用户也可以申请新作者入驻、绑定已有作者或切换绑定；所有申请必须经超级管理员审核，绑定历史永久保留。

## 角色与权限

- 普通用户：浏览、搜索、收藏和提交作者申请。
- 作者：管理自己绑定的作者资料、分类和作品。
- 内容管理员：管理全部作者和作品。
- 超级管理员：拥有全部权限，并负责申请审核、账号管理、删除恢复和操作日志。

每次写操作都在服务端校验角色和资源归属，不能仅依赖前端隐藏按钮。作者不能通过修改请求参数访问其他作者的数据。

## 页面

### 首页

首页采用已确认的编辑精选式与作者焦点式组合：

1. 精选作者大卡。
2. 搜索框与 LAB/WCGlass 快速筛选。
3. 全部作者卡片网格。
4. 最新作品。
5. 全部作品入口。

作者卡展示头像、作者名称、简介、作品数量、代表作品图和进入合集按钮。

### 作者合集页

顶部展示作者资料、公开微信 ID、二维码和作品数量。下方按作者自定义分类纵向展示所有作品，不进入单独作品详情页。

作者可以新增、改名、删除和排序自己的分类，例如卡片、主题、气泡、组件。每件作品只属于一个分类，分类和分类内作品都可调整显示顺序。未分类作品显示在系统生成的“其他作品”中；删除分类不会删除作品，只会让作品回到“其他作品”。

### 作品胶囊卡

桌面端上部左右分栏，左侧主图、右侧完整信息；手机端改为上下排列。卡片展示作品名称、作者、支持环境、直购价、转发价、功能说明、转发要求、购买须知、当前版本、更新时间、联系作者和收藏按钮。

卡片下方展示约四张上机预览图。手机端横向滑动；点击图片打开灯箱，不跳转详情页。较长的转发要求和购买须知在手机端默认折叠。

### 其他页面

- 全部作者页。
- 全部作品页。
- 收藏页。
- 登录与注册页。
- 用户设置页。
- 作者申请页。
- 管理后台。
- 404 页面。

手机底部导航为首页、作者、收藏、我的。

## 作品与销售状态

作品通常同时支持 LAB 和 WCGlass，但后台仍可分别设置。插件需要保持最新版本，作品版本记录可填写最低兼容版本。

价格固定为人民币，数据库以分为单位保存。作品销售状态为草稿、已发布、已下架和已删除。删除为可恢复的软删除；已下架作品仍可显示，但不显示购买按钮。

## 搜索、收藏与统计

游客可浏览、搜索、筛选和查看作者联系方式。登录仅用于收藏、账号设置和作者申请。

搜索支持作品名称和作者名称；筛选支持 LAB/WCGlass；排序支持最新发布和最近更新。不建设热门排行、关注作者和通知。

收藏按用户和作品唯一约束，不能重复收藏。作品直接保存浏览次数、收藏次数和联系点击次数，首期不建设复杂事件分析系统。

## 管理后台

后台包括：

- 作者管理与作者账号启停。
- 作者申请、绑定和切换审核。
- 作者自定义分类管理。
- 作品新建、编辑、排序、上下架、软删除和恢复。
- 主图与多张预览图上传、排序。
- 作品版本和更新日志。
- 微信笔记生成草稿。
- 简单数据面板。
- 用户和角色管理。
- 重要后台操作日志。

微信笔记按作者的固定模板解析作品名称、作者、环境、价格、说明、转发要求、购买须知和版本号。解析结果只能生成草稿，管理员或作者确认修改后才能发布。图片必须单独上传。

## 数据模型

主要数据表为：

- `users`：账号、微信 ID、昵称、头像、密码哈希、角色和状态。
- `authors`：作者公开资料、公开联系方式、二维码和绑定账号。
- `author_applications`：新作者入驻、已有作者绑定和切换申请。
- `author_binding_history`：绑定、解绑和切换历史。
- `author_categories`：作者自定义分类及显示顺序。
- `works`：作品内容、价格、环境、状态、分类和分类内顺序。
- `work_images`：上机预览图及顺序。
- `work_versions`：版本号、更新时间、更新内容、最低插件版本和已知问题。
- `favorites`：用户收藏，用户与作品组合唯一。
- `assets`：头像、二维码、主图和预览图元数据。
- `import_drafts`：微信笔记原文和解析草稿。
- `audit_logs`：重要后台操作及修改前后数据。

所有主键使用 UUID，时间以 UTC 保存并按中国时区显示。删除分类不会删除作品，删除作品和图片默认采用软删除。

## 技术架构

前台、后台和接口使用同一个 Next.js TypeScript 项目：

- Next.js App Router。
- TypeScript 严格模式。
- Tailwind CSS。
- PostgreSQL 与 Prisma。
- Auth.js 账号会话。
- Argon2id 密码哈希。
- Zod 服务端表单校验。
- 腾讯云 COS 生产图片存储；本地开发使用本地图片目录。
- 香港服务器与 PostgreSQL，适配暂时没有备案域名的部署条件。

不拆分微服务，不引入大型后台框架，不为单次逻辑创建抽象层。

## 安全与质量

- 使用 HttpOnly、Secure、SameSite Cookie。
- 注册、登录和高频写操作限流。
- 服务端验证权限、数据归属和 Origin。
- React 默认转义输出，作品说明不接受任意 HTML。
- 图片校验真实格式、大小和尺寸。
- 微信 ID、密码哈希和会话信息不写入操作日志。
- 自动生成基础 SEO；作者可覆盖自己的 SEO 标题和描述。
- 使用 Vitest 测试领域逻辑，Playwright 验证关键用户流程。

## 开发阶段

### 第一阶段

数据库、注册登录、基础权限、作者管理、作者分类、作品管理、图片上传、版本记录、首页、作者合集页、作品胶囊卡、公开微信联系方式、响应式与深色模式。

验收标准：管理员能发布内容；作者只能管理自己的资料、分类和作品；游客能在手机和桌面端完整浏览并联系作者；作品可以下架、软删除和恢复。

### 第二阶段

搜索、LAB/WCGlass 筛选、最新排序、收藏与收藏页、图片灯箱、手机预览图滑动、简单浏览与联系次数。

验收标准：游客搜索和筛选正常；收藏必须登录且不可重复；图片预览支持触屏、键盘和关闭操作。

### 第三阶段

作者入驻与切换审核、微信笔记草稿导入、简单数据面板、完整操作日志和备份恢复验证。

验收标准：一个作者不会同时绑定两个账号；导入内容不能绕过草稿确认；误删作品能够恢复；重要修改可以查看前后差异。

## 明确不做

- 支付、订单、购买验证和文件下载。
- 作者关注、站内通知、热门排行和推荐算法。
- 多语言、邮件、短信和微信授权登录。
- 全站复杂标签和多分类体系。
- 独立作品详情页。
- 站内消息和客服后台。
